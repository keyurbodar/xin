# 20 · Build order

Each step ends with a passing proof. Proofs run under `vitest-pool-workers` with the pi faux provider.

Read with: [01 Host](./architecture/01-host.md) through [11 Failures and cost](./architecture/11-failures-and-cost.md) for the section each milestone builds.

## M0 · Home DO host loop, migrations, Worker auth

**Builds**: Home DO host loop (§1), migrations, Worker auth.

**Proof (test that must pass)**: evict mid-run, run the alarm: answered exactly once. Subrequest stress test.

**Depends on**: nothing.

**Parallel with**: nothing.

## M1 · ops, receipts, wire protocol

**Builds**: ops + receipts + wire protocol (§3–4), plus the minimal plugin host: `definePlugin`, the bundled plugin list, and `reconcile()` with requires/provides. Every later feature (M2–M7) ships as a plugin against this contract. M8 adds permissions, sealed secrets, skills, MCP and schedules on top.

**Proof (test that must pass)**: duplicate cmd → one effect. Hibernate, reconnect, snapshot equals state.

**Depends on**: M0.

**Parallel with**: nothing.

## M2 · intake and dispatch

**Builds**: intake + dispatch (§5–6).

**Proof (test that must pass)**: 3 msgs → 1 turn. Stop aborts. Restart before tools, steer after.

**Depends on**: M1.

**Parallel with**: M3, M4.

## M3 · models

**Builds**: models (§7): credentials, catalog, picker op, `set_model`.

**Proof (test that must pass)**: mid-run switch: the next request uses the new model. A smaller window triggers compaction.

**Depends on**: M1.

**Parallel with**: M2, M4.

## M4 · files

**Builds**: files (§14).

**Proof (test that must pass)**: pi env conformance on R2Env. Upload bypasses the DO.

**Depends on**: M1.

**Parallel with**: M2, M3.

## M5 · orchestrator and threads

**Builds**: orchestrator + threads (§8–9).

**Proof (test that must pass)**: 8 threads finishing together → 1 coordinator turn. Coordinator stop leaves threads running.

**Depends on**: M2.

**Parallel with**: M7, M8.

## M6 · jobs, questions, watchdog

**Builds**: jobs, questions, watchdog (§10–12).

**Proof (test that must pass)**: 1 s tool inline, 20 s tool "started" then a report. Hung tool → failure report ≤ 2.5 min.

**Depends on**: M5.

**Parallel with**: M9.

## M7 · memory

**Builds**: memory (§13).

**Proof (test that must pass)**: fact said once → in profile after an idle pass. Forget removes it. Replayed remember → 1 row.

**Depends on**: M1 and M4.

**Parallel with**: M2, M3, M5, M8.

## M8 · plugin host, skills, MCP, schedules

**Builds**: plugin host, skills, MCP, schedules (§15–16).

**Proof (test that must pass)**: broken plugin isolated (now `src/kernel/kernel.test.ts`). Schedule fires once per slot. The `net` allowlist proof was retired in P1 with the facade: in-process plugins are trusted, as in dsh.

**Depends on**: M1.

**Parallel with**: M2, M3, M4, M5, M7.

## M9 · push and cost guard

**Builds**: push + cost guard (§4, §18).

**Proof (test that must pass)**: push only when no socket. Row bound per scenario.

**Depends on**: M1 and M5.

**Parallel with**: M6.

## P1 · everything is a plugin (dsh model)

**Builds**: the Cordis kernel (§15 rewritten): kernel services as rows, layered composition (bundles, profile patch, owner patch), the plugin manager ops and agent tool, `system.version`/`restart`/`update` with a deployer seam, the `scripts/xin.ts plugin` CLI and the in-repo `plugins/time` package.

**Proof (test that must pass)**: `src/kernel/kernel.test.ts` and `src/kernel/tools.test.ts`: live configure with schema validation, persistence across eviction, reset to bundle, disable/enable, required-row guard, a failing row isolated, `ops/before` policy, scoped secrets, ready work for a late row, soft restart, deployer seam, agent tool gated by `allowAgent`, the time plugin reconfigured live. The whole earlier suite passes on the kernel unchanged in behaviour.

**Depends on**: M0–M9.

## P2 · every feature is a package

**Builds**: each feature moved to `plugins/<name>/` with a `package.json` `xin` field and an `index.ts` entry; `src/catalog.ts` keeps only the required kernel rows, and `src/catalog.gen.ts` is generated by `bun scripts/xin.ts plugin generate`.

**Proof (test that must pass)**: the whole suite passes unchanged after the move, and `bun scripts/xin.ts plugin list` shows every feature package enabled.

**Depends on**: P1.

## P3 · tools are their own rows

**Builds**: every model-facing tool set is a `tool-<name>` row (`tool-files`, `tool-models`, `tool-memory`, `tool-questions`, `tool-skills`, `tool-schedules`, `tool-orchestrator`, `tool-mcp`, `tool-plugins`; `time` is already a tool-only row) that injects its service through `src/contracts/<key>.ts`.

**Proof (test that must pass)**: `plugins/<name>/tools.test.ts` per package: disabling the tool row removes its tools from the next model request while the service row stays active and its ops still work; re-enabling restores them.

**Depends on**: P2.

## P4 · features meet only through services

**Builds**: shared docs, schemas and pure helpers in `src/contracts/` (workspace, threaddoc, jobs, intake, models); services `intake`, `push`, `jobs`, `watchdog`, `models.ownerDefaults`, `threads.report`; `hostModule(name, create, uses)` injects the services a feature calls; `scripts/boundaries.ts` (part of `lint`) rejects any import from one plugin into another.

**Proof (test that must pass)**: `src/kernel/swap.test.ts`: with the `files` row disabled `tool-files` goes pending, an inserted in-memory `fake-files` row provides `files`, and pi's write/read tools work against it; restoring the real row brings R2 back. The whole suite passes with zero boundary violations.

**Depends on**: P3.

## P5 · native plugins, presets and install from the client

**Builds**: every feature is a native Cordis plugin (`name`, `inject`, `apply(ctx)`); the `hostModule` adapter, `HostModule` and `ModuleDeps` are deleted; `boundaries.ts` checks that only a file declaring `inject` reads `ctx.<service>` and that it lists each one. Events `intake/batch` (waterfall: rewrite or drop a claimed batch) and `thread/settled` (emit, at least once). Ops `plugin.install`, `plugin.uninstall`, `plugin.packages`, the `GET /v1/build/packages` route, boot reconcile, `bun scripts/xin.ts plugin sync`, and `docs/deploy/install-pipeline.md`. The `presets` plugin: named tool-row allowlists in its config, assigned per project.

**Proof (test that must pass)**: `plugins/intake/batch.test.ts` (a listener rewrites the text the model sees; another drops the batch), `plugins/orchestrator/settled.test.ts` (one event with the result), `src/kernel/install.test.ts` (recording, idempotency, rejection, deployer payload, reconcile across eviction, owner-only route), `plugins/presets/presets.test.ts` (a preset hides tool rows from the coordinator and its threads, survives eviction, falls back to the default). The whole suite passes with zero boundary violations.

**Depends on**: P4.

## P6 · runtime bundles and contribution rows

**Builds**: a fourth layer of runtime bundles (`kv` `plugins.bundles`) between the profile patch and the owner patch, mounted live with rollback (`docs/plan/architecture/12-market.md` §Runtime bundles). The `packages` service gains `bundles`, `put`, `remove` and `rollback`, with ops `bundle.list`, `bundle.put` (local), `bundle.remove` and `bundle.rollback`. Contribution rows `prompt`, `skill`, `mcp-server` and `preset`. `XIN_VERSION` in the generated catalog. The semver subset moves to `src/semver.ts`.

**Proof (test that must pass)**: `src/kernel/bundles.test.ts` (a local bundle of a prompt and a skill mounts live and the model sees both; an update replaces it; a bundle with a failing row rolls back to the previous version; rollback and remove; an owner config override survives an update; everything survives eviction; invalid bundles are rejected whole), plus a test per contribution row.

**Depends on**: P5.

## P7 · market, discovery and updates

**Builds**: the `market` plugin (`docs/plan/architecture/12-market.md` §Market): indexes plus npm keyword search, statuses, `market.search`, `market.entry`, `market.install`, `market.update`, `market.refresh`, `market.updates`, the daily update check with the `market` home part, and verified tarball fetch (sha512, gunzip, ustar, `$file` inlining).

**Proof (test that must pass)**: `plugins/market/market.test.ts` against a fake registry transport: Lahn publishes 1.1.0 of an installed bundle, the check reports one update, `market.update` mounts 1.1.0 live, and `bundle.rollback` returns to 1.0.0; a code package update records `name@1.1.0` pending; a tarball with a wrong integrity is refused; an incompatible `engines.xin` is never offered.

**Depends on**: P6.

## P8 · setups: bundle patches, profiles, export, wider presets

**Builds**: bundle `patch` entries on compiled rows; the `profiles` kernel row with `profile.list`, `profile.save`, `profile.switch`, `profile.delete`, `profile.export`; presets that select prompt rows and can be assigned per conversation (`docs/plan/architecture/12-market.md` §Setups and §Presets beyond tools).

**Proof (test that must pass)**: `src/kernel/profiles.test.ts` (save two profiles with different bundles and a config override, switch between them and see the rows and config change live, a switch that breaks a required row rolls back, delete, export produces a package.json that `bundle.put` installs elsewhere with the same effect, survives eviction) and `src/kernel/bundles.test.ts` patch cases; `plugins/presets/presets.test.ts` (a preset hides a prompt row from the model; a conversation assignment wins over the project's and can be cleared).

**Depends on**: P7.

## P9 · match dsh: remove what dsh lacks

**Builds**: the plugin, bundle and market layer cut to dsh's mechanisms (owner rule 2026-11-07, `docs/plan/architecture/12-market.md`). Removed: `plugin.insert`, `plugin.remove`, `plugin.reset`, the `multiple` flag, `allowAgent`, row-scoped secrets (now named credentials with `${credential:REF}`), `bundle.rollback` and the stored previous version, `p#x` row namespacing, `superseded`, the `prompt` and `skill` contribution rows, the `profiles` row and its ops, per-project preset assignment and the preset map in the registry config, npm keyword search, the scheduled update check with `checkHours`, the `market` home part and `market.updates`, the `latest` and deprecated rules, the tarball host check and `$file` inlining. Fixed: indexes are parsed as dsh format 1 (`plugins`, per-version `source` and `engines`). Statuses are dsh's.

**Proof (test that must pass)**: `plugins/market/market.test.ts` against a real dsh-shaped format-1 index and a fake registry transport: an index entry's 1.1.0 shows `update-available` over an installed 1.0.0, `market.update` mounts 1.1.0 live, a 1.1.0 whose row fails restores 1.0.0, an older version is refused, a git-sourced version records a pending `git+` spec, a wrong integrity is refused; `src/kernel/bundles.test.ts` (a fresh install with a failing row stays installed and reports it; a bundle row adds the `fake-files` row for the swap test); `plugins/presets/presets.test.ts` (preset rows, per-conversation selection only while blank, threads inherit); `plugins/mcp/server.test.ts` (a `${credential:REF}` header resolves from `secret.set`). The whole suite passes with zero boundary violations.

**Depends on**: P8.

## P10 · approval (dsh `tools/pre-execute`, `user-approval`)

**Builds**: a `tools/pre-execute` waterfall over model tool calls (allow, deny, cancel, ask) and a swappable `user-approval` service that answers `ask` through a question card. Nothing else.

**Depends on**: P9.

## P11 · always-on: the clock, manual compaction and the loop guard

**Builds**: `docs/plan/architecture/13-always-on.md`. The `time` row becomes dsh `context/time-context`: a `GenerationTask.beforeRequest` hook appends a durable reading (ISO time, zone, elapsed) when the last one is older than `refreshIntervalMs`, and the `current_time` tool is removed. The new `compact` row adds `conv.compact` (dsh `command-compact`) over pi's manual `conversation.compact()`, answering `busy` during a live run. The new `guard` row is dsh `guard/repeat-tool-reminder`: identical `{name, arguments}` repeats counted per conversation, reminders appended to the tool result at 3, 5 and 8, cleared by a new owner message, advisory only.

**Proof (test that must pass)**: `plugins/time/time.test.ts` (one reading before the first request, a second one suppressed inside `refreshIntervalMs` and written when `0`, elapsed against the last message then against the previous reading, a bad zone fails the row); `plugins/compact/compact.test.ts` (compacts an idle conversation, `busy` while a run is live, `instructions` reach the summarizer); `plugins/guard/guard.test.ts` (reminders at 3, 5 and 8 with the arguments preview, no reminder for changing arguments, counts cleared by a new message, a blocked or error result still counts). The whole suite passes with zero boundary violations.

**Depends on**: P9. Parallel with P12 and P13.

## P12 · scheduled tasks, dsh shape

**Builds**: `docs/plan/architecture/13-always-on.md` §Scheduled tasks (dsh `schedule`, `tool-schedule`). The task record gains `title`, `active` and `updatedAt`, and the target becomes `this_session | new_once | new`. Four tools replace `schedule`/`unschedule`: `schedule_create`, `schedule_list`, `schedule_view`, `schedule_edit` with `expectedUpdatedAt` conflicts, pause and resume, `schedule_not_found`, the `subagent_session` refusal and the shared authorization section. Ops keep `schedule.create`, `schedule.cancel`, `schedule.list` and gain `schedule.edit`, `schedule.view`.

**Proof (test that must pass)**: `plugins/schedules/tools.test.ts` (create, list with `active` filter and paging, view an unknown id, edit a prompt and an rrule, pause stops delivery and resume restarts it, a stale `expectedUpdatedAt` changes nothing, a delegated caller is refused) and `plugins/schedules/schedules.test.ts` (all three targets deliver once where they should, an edit survives eviction, a resume with an exhausted rule is refused). The whole suite passes with zero boundary violations.

**Depends on**: P9. Parallel with P11 and P13.

## P13 · goals (dsh `goal`, `tool-goal`, `goal-round-driver`)

**Builds**: `docs/plan/architecture/13-always-on.md` §Goals. New rows `goals` (state in `kv` per conversation, ops `goal.get` and `goal.set` with a discriminated action, compare-and-set on `{id, revision}`, instance-local armed set), `tool-goals` (`get_goal`, `create_goal`, `update_goal` with dsh's schemas, shared output JSON and policy paragraph) and `goal-rounds` (the driver). The driver reserves a round from `GenerationTask.afterRun` by enqueuing an `inbound` row of kind `job` whose command id starts `goal:`, the claim re-checks the goal and spends exactly one round, the cap blocks with code `round-limit`, and a pending round is dropped when an owner message arrives.

**Proof (test that must pass)**: `plugins/goals/goals.test.ts` (create, edit, pause, resume, complete, block and clear with revision conflicts; one goal per conversation; an unfinished goal must be cleared before another; armed is cleared by a new instance); `plugins/goals/rounds.test.ts` (a goal runs round after round while idle, each round is one turn with the `<goal_round>` prompt, a stale reservation spends no round, the cap blocks with `round-limit`, an owner message cancels a pending round, a disarmed goal does not continue after eviction, and disabling the row leaves the goal usable by hand); `plugins/goals/tools.test.ts` (the three tools answer the shared JSON, `blocked_reason` is required only for `blocked`). The whole suite passes with zero boundary violations.

**Depends on**: P9. Parallel with P11 and P12.

## P14 · the web client

**Builds**: `docs/plan/architecture/14-client.md`. A SolidJS + Vite + Tailwind client in `web/`, a separate package so the Worker gate never compiles it, built against the Doop canvas `fTzMMHDuiN`: owner-token sign-in (O1), Home (D3), project chat with the right panel (D1, D2, D5, D6, D8), Inbox (D7), the new-project dialog (D4), Extensions (E1–E7), Settings (S1–S4), Onboarding (O2–O5), the landing page (L1), the ⌘K palette (D6), the D Grid status glyphs (I2), skullet skeletons, torph counters, and the F4 motion tokens. Below 1024px the sidebar becomes a bottom tab bar (M1) and the panel becomes a bottom sheet (M3). It adds the owner-only ops the agent never asks for: `request.list` (the Inbox's question text and options), `usage.summary` (spend and tokens from pi's ledger, bucketed by UTC day into `usage_daily`, with `cap`, `alert` and `byProject`), `usage.cap`/`usage.cap.set` and `usage.alert`/`usage.alert.set` (the S2 cap and daily alert, which the models plugin also enforces and alerts on), the notification ops `notify.prefs`/`notify.set`, `notify.quiet`/`notify.quiet.set` and `push.test`/`push.list`, `history.page` (older entries than the socket's bounded snapshot, paged from the view's own `before`), `job.list` (the panel's Jobs tab), `owner.read`/`owner.set` (the S1 name and the `<owner>` instructions section), `session.list`/`session.close`/`session.rotate` (the S4 signed-in sockets and the token's revocation path), `system.metrics` and `system.logs` (the S4 service figures and the downloaded log ring), `skill.read` and `mcp.tools` (the E7 skill body and the E6 connector tools), `memory.profile.write` (the edited dreamer profile), the prompt store `prompt.list`/`prompt.put`/`prompt.delete` behind E7's slash commands, and the market controls `market.policy`, `market.refresh`, `market.skip`/`unskip`/`skipped` and `market.rollback`. Each reads state that already exists, except the two small kv singletons behind the cap and quiet hours.

**Proof (test that must pass)**: `web/` builds and typechecks (`bun run build`, `bun run typecheck`), and the verification skill drives every route once against the real Worker and a real `wrangler dev` home: sign in with the owner token, Home renders the greeting and the five counts from a live snapshot, the palette opens on ⌘K and navigates, a project route renders its transcript from the conversation stream, Inbox lists what waits, Extensions and Settings read their real ops, and a schedule pauses and resumes. Each route is captured as a screenshot compared with its frame.

**Depends on**: P13.
